# 服务器端重加权

> **审核后的当前说明：** 单训练seed、旧覆盖指标、数据适用性限制同时存在。结果相同不证明梯度为零。预算不足时修复版明确报错；main.py为补丁库。
> 正确入口和能力边界见 [代码说明](../../README.md)；下方为历史线路说明，其结论以根README和结论状态表为准。


**问的问题**：稀有分量拿不到采样名额，强行让它被采到，能不能救回来。

两组补丁：

- **覆盖保证采样**：`gmm_sampling` 里每个局部分量至少采 1 点
- **使用量下限**：`ELBO_Loss_server` 里对责任度低于 `1/(2K)` 的分量加惩罚

**结论**：覆盖保证采样确实改变了行为（生成落在稀有区 9.8% → 15.8%），但稀有覆盖率反而下降；
使用量下限**从未生效**（惩罚值 0.03 vs server loss ≈ 2.0），结果与对照组逐位相同。

**重要局限**：这条线是在 yeast 上做的，而 yeast 的稀有类在输入空间 1-近邻纯度低于随机
（0.018 / 0.029 / 0.000，占比 2.3% / 1.5% / 0.3%）。**因此这些负面结果不能推广到其他数据集**，
也不能用来否定服务器端方向。

详见 `docs/reports/13_server_reweighting.md`。
