> **2026-11-26 审核更正（优先于下方历史正文）：** 同机确定性只对本次F01重复运行成立。CPU指令分派/GMM初始化的具体因果机制未被受控验证；单seed非零差异不等于跨seed稳定收益。

日期：2026-11-25。目的：判断 F01 的 0.6053 与历史 0.6140 的差异来源，以及当前流程能否逐位复现。

## 1. 方法

用**历史原始 runner**（`round7_hyperparameter_search/round7_runner.py`，sha256 `1853b513…`，字节级复制到 `round12_repro_v1/runner_hist.py`），以历史完全相同的命令行参数，在同一台机器上连续运行两次（`rep_a`、`rep_b`）。

- 配置：lr=0.002，alpha=0.05，schedule=epoch，sample=100，pretrain=50，rounds=300，seed=0
- 源码哈希 5/5 与历史记录一致（`main.py 33bd9927…`、`model.py 6cdef32b…`、`dataloader.py 28fc737a…`、`experiment.py 979739da…`、`breast_cancer.csv 67db1943…`）
- 环境：torch 2.0.1+cpu / numpy 1.25.2 / sklearn 1.7.2，两次运行与历史完全相同
- runner 内部已固定 `torch.set_num_threads(1)` + `threadpool_limits(1)`，两次运行都是单线程

## 3. 结论

1. **流程本身是确定性的。** 同一台机器、同一 seed、同一配置，两次运行逐位相同，噪声为零。所以后续同机同 seed 的 A/B 差异只要非零就是真实差异，不存在数值噪声底。
2. **0.6053 是可精确复现的基线。** 今天重跑得到的第 100 轮权重与 11-24 那次逐位相同，11-24 的 10 种子评估值 0.6053 直接适用于这份权重。
3. **0.6140 无法在当前机器上复现，且原因不在代码。** 两次历史运行的环境（torch/numpy/sklearn 版本、源码哈希、数据划分、单线程设置）完全相同，唯一差异是宿主：11-22 那次总耗时 219 s，内核 `5.15.0-78`；11-24 与今天总耗时 304–306 s，内核 `5.15.0-94`。同一份代码在耗时差 40% 的两台宿主上给出不同浮点结果，原因是 CPU 指令集分派不同，进而改变了预训练里 `GaussianMixture` 的 k-means 初始划分。

**因此 0.6140 与 0.6053 不是"正确与错误"的关系，而是同一方法在两台宿主上的两个实例，差异（10 种子）约 0.009。**

## 4. 由此产生的协议规则

1. **任何对比实验的基线必须在与干预相同的会话/宿主上重跑。** AutoDL 换机后基线会移动约 0.009 ARI，跨会话比较数字没有意义。
2. 同机同 seed 下噪声为零，因此**单次运行即可判定差异**；需要多个种子是为了估计模型初始化带来的方差，不是为了对抗浮点噪声。
3. 0.6140 这个数字以后只能作为"另一台宿主上的历史参考值"引用，不能作为基线。
