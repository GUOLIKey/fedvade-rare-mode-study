# FedVaDE 稀有模式研究：实验记录与结论

本仓库记录一项围绕 FedVaDE 的研究：原本希望改善客户端独有稀有模式的全局生成，随后发现原命题、数据适用性和覆盖指标都需要重新检查。**这是研究档案，不是已经证明有效的新方法。**

2026-11-26 审核后，结论按证据强度重新分级。历史报告保留当时正文；顶部更正和本 README 优先。旧版整理代码存在回归，不能据此否认历史运行，也不能把旧结果称为当前代码已经复现的结果。

## 一、我们问了什么

在 FedVaDE 原训练框架内，能否让全局生成模型保留客户端的稀有数据模式？

研究中发现：作者的随机 Non-IID 划分包含跨客户端重复样本，不保证客户端独有类别；Breast Cancer 不能直接验证真实的客户端独有稀有类别。后来构造了 Fashion-MNIST 的类内 K-Means 碎片化划分，以研究更可分的数据。这个划分是本项目实现，不能称为 FedHCA 的原始划分。

## 二、需要先知道的协议

- 作者模型为 encoder/decoder + 对角高斯混合。局部初始分量数使用真实标签的类别数，不能称为无标签发现 K。
- 每轮按客户端记录数平均 encoder/decoder；服务器从局部混合模型合计采样，再训练服务器模型。客户端接收的是平均参数，而不是服务器训练后的参数。
- 作者客户端 LR 调度按 mini-batch 步进；改变每轮记录数，也改变优化次数和 LR 轨迹。F01 的每轮 LR 版本与作者版本必须分开。
- `predict()` 采样潜变量；训练种子、预测推理种子、生成种子、覆盖参考集划分种子是不同的随机性。
- 历史 ARI 多在拼接的客户端记录上计算，重复样本会重复计权。修复版另提供 `unique_full` 评价；它仍是样本内评价，不是独立测试集。两种口径不得混用。

## 三、研究问题如何变化

| 阶段 | 问题 | 当前状态 |
|---|---|---|
| 初始 | 客户端独有稀有模式是否丢失 | 作者数据和划分尚不足以验证原命题 |
| 局部/服务器诊断 | 局部分量多、采样预算少是否造成损失 | 有观察和短程干预，尚未识别普遍失败机制 |
| Fashion-MNIST | 鞋包类是否被系统性丢弃 | 原全局阈值指标有偏，旧证据撤回 |
| 划分比较 | 碎片化组为何低于作者划分组 | 差异存在；数据暴露量、优化预算和评价权重混淆未隔离 |

## 四、做过什么实验

### 4.1 工程参考与历史复现

工程参考 C13-s1 使用作者训练框架、alpha=0.05，在 Breast Cancer 的第 300 轮记录 ARI=0.6381。同配置三个训练种子为 0.5774 / 0.6381 / 0.3212；报告均值约 0.5123、样本 SD=0.1682。**单次参考不代表平均性能，也不是作者默认 alpha=0.01 的稳定复现。**

作者交付权重的历史重评记录为 0.6295 ± 0.0088；本次十推理种子重评为均值0.6294720、ddof0 SD0.0083635。同组draws按ddof1得约0.008816，与历史四位0.0088相容；应明确统计口径。C13-s1的独立冻结权重复评已恢复相同的0.6381354/SD0.00729763；这验证评价，不等于完成从头重训。C13 seed2的第300轮权重未在已核查run目录找到，三seed表中的该值仍引用原日志。不同 evaluator、宿主或评价记录集合上的结果不能直接视为同一次测量。C13-s1 的原始推理输出已找回：ARI均值0.6381354、推理SD0.00729763（十推理种子，原evaluator的ddof=0）。原baseline.md的“约0.005”已更正。该汇总training_seed字段为0而运行config为1，作为元数据冲突保留并记录。

F01 历史值 0.6140 / 0.6053 来自探索性配置/轮次选择，不能作为无偏性能估计。报告03在相同宿主、种子和流程下复跑 F01 得到逐位一致；这不等于已经验证 C13 或所有 GPU 运行都逐位确定。跨宿主差异的具体 CPU/BLAS 机制仍不确定。

来源：[基线约定](docs/baseline.md)、[报告19：找回的原始输出与独立重评](docs/reports/19_audit_recovered_evidence.md)、报告 [01](docs/reports/01_reproduction_f01.md)、[02](docs/reports/02_original_search_protocol.md)、[03](docs/reports/03_host_determinism.md)、[07](docs/reports/07_ablation.md)。

### 4.2 超参、随机性与消融

- F01 三个训练种子的 ARI@100 为 0.6053 / 0.6509 / 0.4291，样本 SD=0.1171。单 checkpoint 推理 SD 的历史值约 0.0045；约 26 倍是**标准差比**，不是方差比，也不是所有配置的常数。
- 固定 flow=777 改 init 的 SD=0.0500；固定 init=0 改 flow 的 SD=0.1009。没有交叉设计，不能估计 74%/18% 的总体贡献或判断交互很小。
- sample 扫描只有一个训练种子；sample 也影响预训练 GMM 初值。因此不能宣布预算瓶颈已被排除。
- alpha=0.05、pretrain=5 的三种子最终值为 0.5778 / 0.5644 / 0.5571，样本 SD=0.0105，约为上述 C13 SD 的 1/16。这是已测三个种子的较低离散度，不证明消除了坏种子失败模式。
- 仅改 LR 步进的三个 @300 配对差为 +0.0226 / +0.0653 / −0.0106，均值约 +0.0258；未建立稳定收益，也未证明无效或等效。

来源：报告 [04](docs/reports/04_hyperparameter_grid.md)、[05](docs/reports/05_variance_decomposition.md)、[06](docs/reports/06_author_defaults.md)、[07](docs/reports/07_ablation.md)。

### 4.3 客户端 ACD / BIC / DPGMM

ACD 的局部冻结实验得到很多低支持分量；其全局验证只做了冻结客户端后的 10 轮服务器更新。ACD−原始的配对 ARI 差为 +0.0008 ± 0.0184，未显示稳定改善。它不是完整联邦训练的有效性结论。BIC 也只应按已执行的局部/短程实验解释。

DPGMM 在固定上限和剪枝设置下保留较多分量，未通过预设预检门槛；没有完整 300 轮结果，也没有完成同 K 对照。平均预算不足是风险解释，不是已经证明的全局失败机制。

来源：报告 [08](docs/reports/08_acd_local.md)、[09](docs/reports/09_acd_global.md)、[18](docs/reports/18_dpgmm_precheck.md)。

### 4.4 服务器 Multi-CA / 重加权

- 冻结 Multi-CA 与同容量 flat 构造的叶成员相同，参数 `allclose`，指标一致。此结果限于所测共同合并树，不是所有层次方法的一般等价定理；参数位级相同未充分验证。
- 完整 warm-start 中，作者支路 ON−OFF 的 ARI 为 −0.0772，F01 支路为 +0.0318；两支路生成 MMD/SWD 和 NLL 改善。全组相对初值退化不能归因于 Multi-CA；ON/OFF 还存在容量差异。
- yeast 的服务器重加权只有单训练种子。旧覆盖指标和数据适用性都有限；不能由低 1-NN 同类比例证明不存在任何可学结构。结果相同不证明惩罚项梯度为零，也不能由标量损失占比推断梯度可忽略。

来源：报告 [10](docs/reports/10_multica_method.md)、[11](docs/reports/11_multica_frozen.md)、[12](docs/reports/12_multica_full_loop.md)、[13](docs/reports/13_server_reweighting.md)。

### 4.5 Fashion-MNIST

| 设定 | ARI@300（三训练种子） | 历史 coverage ratio v2 |
|---|---:|---:|
| 平衡 / 碎片化 | 0.2585 ± 0.030 | 1.113 |
| 长尾 / 碎片化 | 0.2170 ± 0.027 | 1.184 |
| 长尾 / 作者划分 | 0.3796 ± 0.076 | 1.009 |

这些是历史口径的描述。作者划分使 10001 条样本形成 45639 条客户端记录；训练暴露量、mini-batch 更新和衰减次数，以及 ARI 的评价记录权重均可能不同。**尚不能把差异单独归因于碎片化。** 平衡与长尾也不是同一个控制条件。两划分的StandardScaler浮点路径也有微小差异（lt10最大约7.63e-6），对结果的影响不确定，见报告20。

hid=20/30 的三种子 ARI@300 分别为 0.3041 / 0.2779；coverage ratio 为 1.106 / 1.120。未观察到明显覆盖改善，不等于证明维度没有影响。报告16的 hid=30 是较早的两种子快照，最新三种子结果见报告17。

审核重评：9个基准模型的旧口径ARI与原输出完全对齐；全量每记录一次的三组均值为0.258634 / 0.217017 / 0.384260，仍不能消除训练暴露与更新预算混淆。完整口径和逐模型证据见[报告20](docs/reports/20_saved_checkpoint_reevaluation.md)。

来源：报告 [14](docs/reports/14_fmnist_baseline.md)、[16](docs/reports/16_correction.md)、[17](docs/reports/17_hiddim_sweep.md)。

### 4.6 coverage ratio v2 的含义与局限

按类把真实数据分成参考集 R 和查询集 Q，生成 |R| 个样本 G：

`ratio(c) = median_{q∈Q_c} min_g ||q−g|| / median_{q∈Q_c} min_r ||q−r||`

1 表示这两个最近邻距离中位数相等，不等于生成分布与真实分布等价。历史覆盖评价固定生成种子0、划分种子0，与 ARI 的十个推理种子不是同一设置。奇数类对半取整，R/Q 不保证恰好等大，但 G 必须与 R 等大。

`G=R` 自检验证实现恒等性，不能单独证明能检测丢类。**实际Fashion-MNIST缺类对照进一步发现：完全移除凉鞋类后ratio约1.10，移除包类后约1.17–1.27，仍在旧“正常范围”内。新ratio也不能用来排除类别丢失。** 详见[报告21](docs/reports/21_metric_missing_class_control.md)。修复版另有合成缺类阳性对照，仍不能据此证明真实数据上所有失真都能被检测。历史表格的逐类值约 0.95–1.55，不能写成全部在 1.0–1.5；未做类间显著性检验。

## 五、撤回与降格

| 旧结论 | 现状态 | 原因 |
|---|---|---|
| 全局模型只覆盖一半类别 | 撤回旧证据支持的断言 | 全局阈值对类几何有偏；未据此证明相反命题 |
| PCA-10 误差证明潜空间装不下鞋包 | 撤回 | 缺少可识别容量限制的对照 |
| GMM 分量分配已造成可测量生成损失 | 撤回因果断言 | 分量观察不足以识别生成损失来源 |
| 新ratio在1.0–1.5证明没有类别丢失 | 撤回排除性推断 | 真实数据缺类阳性对照给出反例，见报告21 |
| oracle 覆盖率低证明解码器无法生成目标类 | 撤回 | 同样使用旧全局阈值 |
| 训练流程贡献74%、初始化18% | 撤回比例归因 | 非交叉设计不能识别总体贡献和交互 |
| sample=100 已最优，预算瓶颈排除 | 撤回排除性结论 | 单种子且影响两个阶段 |
| 碎片化本身显著损害 FedVaDE | 降为混淆观察 | 数据暴露、优化轨迹、评价权重同时变化 |
| LR 每轮步进有效／无效 | 降为尚未确定 | 联合改动未隔离；三种子不能证明等效 |
| 局部K的三条路线均失败 | 降为各阶段已测结果 | 代理实验和预检不等于端到端失败 |

## 六、目前能保留的七条观察

1. alpha=0.05 的 C13-s1 单次工程参考记录为 0.6381；三种子离散度很大。
2. 已测 F01 设置下，训练种子离散度明显大于同 checkpoint 推理离散度。
3. 初始化和训练流程随机性均能影响结果；总体贡献比例未知。
4. alpha=0.05、pretrain=5 在三个已测种子上最终离散度较小；泛化稳定性未知。
5. 三套 Fashion-MNIST 设定的历史指标不同；划分本身的效应尚未隔离。
6. ACD/BIC 短程验证未显示稳定全局改善；DPGMM 只完成预检。
7. 已测冻结 Multi-CA 和对应同容量 flat 构造数值一致；完整 warm-start 的效果依条件而异。

## 七、未解决的问题

原始稀有模式命题的可检验定义、数据适用性、划分/重复暴露/更新预算的独立贡献、覆盖指标对真实缺类的灵敏度，以及多种子端到端方法效果均未解决。新增受控训练必须另立实验协议；不从旧观察补写机制结论。

## 八、复现与 Mac／服务器分工

Mac 保存代码、报告、清单和证据备份；服务器保存完整数据与运行产物并执行数值验证。大文件不进 Git 本身不妨碍复现，但必须有获取方式、版本和校验。

详见 [复现说明](docs/reproducibility.md)、[结论状态](docs/conclusion_status.md)、[审核修复记录](docs/audit_repair.md)、[交付与恢复说明](docs/repair_delivery.md)。

复现要求：先确认现象适用性；比较须有匹配对照；区分各类种子；指标有恒等和阳性对照；保存宿主/环境/实际源码与数据哈希。固定工程参考不替代配对多种子基线。
